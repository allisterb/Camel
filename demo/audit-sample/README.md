# Camel audit-trail sample (SRL-2018 rd-01)

A real, self-contained demonstration of Camel's **audit trail** — the evidence that any finding in an agent's
report traces to the specific tool execution that produced it, and that a case is reconstructable from the logs
alone (Find Evil! judging criterion 5).

| File | What it is |
|------|------------|
| [`audit-srl-2018-rd01.clef`](audit-srl-2018-rd01.clef) | The per-case audit log: structured JSON ([CLEF](https://clef-json.org/)), one event per line, for case `srl-2018-rd01`. Generated from real rd-01 analysis. |
| [`THREE_CLAIM_TRACE.md`](THREE_CLAIM_TRACE.md) | A worked three-claim trace: three findings from the agent's report, each traced to the command that produced it. **Start here.** |
| [`trace.sh`](trace.sh) | One-command tracer: `./trace.sh <executionId>` prints every tool execution behind a cited finding. Needs `jq` (on SIFT). |

## How it was produced

Each Camel session sets a case id (the `SetCaseId` MCP tool); every tool execution is then written to
`audit-<caseId>.clef`, enriched ambiently via Serilog `LogContext` with the case, the per-call execution id, and
the workflow/toolkit/command that ran it. Every `Execute` result ends with an audit handle —
`[audit] case=<caseId> execution=<id>` — that the agent cites next to each finding.

This sample was generated by the committed reproducer
[`tests/Camel.Tests.Workflows/AuditSampleGenerator.cs`](../../tests/Camel.Tests.Workflows/AuditSampleGenerator.cs),
which runs three real rd-01 analysis executions (WMI persistence, Amcache execution evidence, `$MFT` records)
through the same workflow → toolkit → environment code paths the MCP server drives, against the rd-01 C: image
mounted at `/mnt/rd01-c`. Regenerate it with:

```bash
CAMEL_GEN_AUDIT_SAMPLE=1 dotnet test tests/Camel.Tests.Workflows/Camel.Tests.Workflows.csproj \
    --filter FullyQualifiedName~AuditSampleGenerator
```

(The generator is skipped in the normal test run unless that env var is set, and requires SSH access to the SIFT
workstation with the rd-01 image mounted.)

## Try the trace

```bash
cd demo/audit-sample
./trace.sh 7f3a9c21      # WMI fileless persistence → squirreldirectory.com C2 cradle
./trace.sh 2e8b14d6      # 227 binaries via AmcacheParser
./trace.sh 9a4f7b03      # 15,433 $MFT records via MFTECmd
```
